# VR Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the immersive program room into a dedicated VR space where three standing students wear headsets and hold controllers in a looping `vr` animation.

**Architecture:** Blender adds a `vr` clip and three fitting empties (`vr_eyes`, `vr_grip_l`, `vr_grip_r`) to every character, and builds four small assets (headset, controller, floor zone, VR screen). The web app merges each gear asset into one vertex-coloured mesh, parents it to the fitting empties, and furnishes the immersive room from a pure layout module instead of the classroom tables.

**Tech Stack:** Blender 5.2.3 headless (`scripts/world.py`), Python `unittest`, three.js, vitest, Playwright browser tests.

**Spec:** `docs/superpowers/specs/2026-11-02-vr-room-design.md`

## Global Constraints

- Only the immersive room changes; other rooms, walkers and terrace students stay as they are.
- No Meshy, no credits, no new character models.
- Performance on the largest campus: at most 150 draw calls and 500,000 triangles including the shadow pass, 60 fps on the reference desktop. If three students do not fit, use two.
- Gear is one mesh with one material per piece, casts no shadow, and is marked `userData.separate = true`.
- Distance models (`-lod1`) wear the headset only; close models wear headset and both controllers.
- A new run directory per result (`runs/vr-NN-*`). Never declare a visual verdict without opening the render.
- Manifests are written by Blender with CRLF line endings; restore with `git checkout -- assets/manifests docs/ASSET_CATALOG.md` after the Python suite rewrites them.
- Shell is zsh: list asset ids explicitly, do not rely on word splitting.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A character GLB without the fitting empties (an older published file, or a partial publish) must not throw: `wearGear` skips missing empties and the room still renders. Test in Task 3.
2. Switching between close view and campus view must keep the headset on whichever model is visible. Pinned by the browser diagnostic in Task 4.
3. Rebuilding the room on a state change must not dispose the shared gear geometry that other rooms or the next build reuse. Test in Task 3.
4. The x-ray view must not leave gear opaque over a see-through building. Checked in Task 5's opened x-ray render.
5. Campuses without the immersive program must not load gear assets at all. Test in Task 4.

- [ ] **Step 4: Implement**

- `author_clips(arm)`: add `clip(arm, 'vr', keys)`, a loop of 73 frames (about 3 s at 24 fps) built with `merged(...)` from world-axis turns like the others. Keys: frame 1 neutral with forearms raised in front (`FOREARMS`-like, about -60°); frame 19 head turned left about 35° and right arm reaching forward; frame 37 head right about 35° with a slight tilt and left arm reaching; frame 55 both arms swept outward; frame 73 equal to frame 1. Arms never rise above the shoulders, so controllers stay clear of the headset. No hip lift.
- `add_fitting(arm, mesh, height)`, called at the end of `student()` after scaling and `author_clips`, with the armature in rest pose:
  - `vr_eyes`: from vertices whose largest weight is the `Head` group, take the head's vertical span; eye height is 45% up from its lowest vertex; the point is the front-most head vertex (most negative Blender Y) within 2 cm of that height, at x = 0. World scale = head width (x span of head vertices) / 0.2 × 0.95.
  - `vr_grip_l` / `vr_grip_r`: centroid of the vertices whose largest weight is `LeftHand` / `RightHand`. World scale = hand length (largest span of those vertices) / 0.14.
  - Each is an empty created in `geometry.current().coll`, given that world matrix (translation and uniform scale, no rotation), then parented to the bone (`parent_type = 'BONE'`, `parent_bone = name`) keeping its world transform.
  - Return the dict unchanged; pivots reach the manifest through `PIVOT_PREFIXES`.
- `glb.py`: `PIVOT_PREFIXES = ('wheel_', 'rotor_', 'joint_', 'head', 'lid', 'vr_')`.

### Task 3: Gear meshes and attachment in the app

**Files:**
- Create: `web/src/world/gear.js`
- Test: `web/test/gear.test.js`

**Interfaces:**
- Consumes: Task 1's empty names; Task 2's asset ids.
- Produces:
  - `gearMesh(asset: { id: string, scene: Object3D }) -> Mesh`: one mesh whose geometry merges every mesh of the asset in the asset's own space, with a `color` attribute taken from each source mesh's `material.color`; material is one shared `MeshStandardMaterial({ vertexColors: true, roughness: .5, name: 'GG_GearVertex' })`; geometry cached per `asset.id` and shared by every returned mesh; `castShadow = false`, `userData.separate = true`, `userData.shared = true`.
  - `wearGear(character: Object3D, kit: Map<string, asset>, { controllers: boolean }) -> number`: parents a `gearMesh` of `equip-vr-headset` to `vr_eyes`, and when `controllers` is true one of `equip-vr-controller` to each of `vr_grip_l` and `vr_grip_r`, all with identity local transform; skips any empty that is missing; returns how many pieces it attached.
  - `clearGear()`: disposes the cached geometries (called where `disposeMaterials` is called).
