# Look Inside a Focused Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whenever a room is in focus, from a click or a host `setFocus`, everything blocking it from the camera becomes a translucent veil or hides, so the visitor sees inside, as the cotizador's campus does.

**Architecture:**
- **Rules:** a pure module decides, from the plan's modules, the focused room and the camera yaw, which modules veil or hide and which of the room's own walls veil.
- **Shell:** each room's shell asset is merged in its own `entity.shell` group, so it can be veiled or swapped on its own. The focused room swaps its merged shell for an unmerged clone whose camera-facing walls take a shared veil material.
- **Runtime:** `create-world.js` applies and clears the x-ray, keeps x-rayed entities out of the batch, and makes picking skip what the visitor cannot see.

**Tech Stack:** three.js, vitest, Playwright browser tests.

**Spec:** `docs/superpowers/specs/2026-11-03-room-xray-design.md`

## Global Constraints

- **When:** the x-ray opens whenever `setFocus` lands on a `type: 'room'` module (click or host); a non-room focus only moves the camera.
- **Clearing it:** `resetView` and `setFocus(null | non-room)` clear it. A click on empty ground does nothing.
- **Above:** `|dx| < 3.9`, `|dz| < 3.45`, `y > room.y + 0.1` → veil. If the module is a room or a roof, its furniture, characters and gear hide.
- **Between:** `along = dx·sin(yaw) + dz·cos(yaw)` in (1.8, 13.5), `lateral = |dx·cos(yaw) − dz·sin(yaw)| < 6.6`, and `y ≥ room.y − 0.3` (any `y` for `tree`).
  - `room`, `roof` and `patio` hide.
  - `balcony`, `gallery`, `stairs`, `landing`, `entrance`, `tree`, `detail`, `support`, `corridor` and `planter` veil.
- **Own walls:**
  - `header` and `sill` always veil.
  - `pier_front` veils when `cos(yaw) > 0.25`.
  - The left side wall (x < 0) veils when `sin(yaw) < −0.25`; the right one (x > 0) when `sin(yaw) > 0.25`.
  - `wall_back`, `accent_back`, `inner_back`, `screen` and `screen_frame` veil when `cos(yaw) < −0.25`.
- **Veil material:** one shared `MeshStandardMaterial`, ivory `#FFF8EC`, `transparent`, opacity 0.22, `depthWrite: false`, casting no shadows.
- **Recompute:** when the focused room or `Math.round(yaw * 4)` changes, and after an `update` builds or removes entities.
- **Picking:** skips hidden objects and veiled non-room modules; a veiled room stays pickable.
- **Performance:** measure close view with the Makerzoid and Electronics rooms focused before any change (baseline). The x-ray adds at most 15 draw calls to it, keeps triangles at most 500,000 and fps within noise of 60. The campus view is unchanged: 142 draw calls and the parity test passing.
- **Evidence:** a new run directory per result (`runs/xray-NN-*`). Never declare a visual verdict without opening the render.
- **Node:** `unset -f node npm npx; export PATH=/home/adawolfs/.nvm/versions/node/v22.23.4/bin:$PATH`, run from `web/`. The dev server must be on 127.0.0.1:4410. After any `git stash`/`checkout` of source files, restart it: its watcher can miss those writes.
- **Commits:** messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. An `update` while a room is open (the school changes in the side panel) must not leave veils on released meshes or a stale unmerged shell, and must reopen the x-ray on the rebuilt room. Pinned by a browser check in Task 3.
2. Focusing a second room while one is open must fully restore the first before opening the second. Pinned in Task 3: after focusing A then B, nothing of A stays veiled or hidden.
3. Turning the camera from front to back of the focused room must swap which own walls veil, without leaving the old ones veiled. Pinned in Task 3 via `xray.ownVeils` before and after `rotate(Math.PI)`.
4. The batch must never contain a veiled or hidden mesh, and must contain everything again after clearing. Pinned in Task 3: the batch source count with the x-ray open is smaller, and after clearing it equals the count before opening.
5. Reduced motion (camera jumps without easing) still opens and clears the x-ray. Pinned in Task 3 with a `reducedMotion: 'reduce'` page.

### Task 3: Open and clear the x-ray

**Files:**
- Modify: `web/src/world/create-world.js` (`applyXray`, `clearXray`, `setFocus`, `resetView`, `tick`, `update`, `scheduleBatch`, `pick`, `getDiagnostics`)
- Create: `web/test/xray.browser.mjs`; add `"test:xray": "node test/xray.browser.mjs"` to `web/package.json`

**Interfaces:**
- Consumes: `xrayBlockers`, `wallVeils`, `OWN_WALLS`, `HIDES_INSIDE` (Task 1); `veilMaterial`, `entity.shell` and `entity.shellAsset` (Task 2).
- Produces: `getDiagnostics().xray`:

  ```js
  { room: string|null, veiled: string[], hidden: string[], ownVeils: string[], batchSources: number }
  ```

  - `ownVeils` lists the part names veiled on the focused room's unmerged shell.
  - `batchSources` is the number of meshes in the current batch.

- [ ] **Step 1: Write the failing browser checks** in `xray.browser.mjs`, on `states[5]`, each in its own block. Each check fails with a message naming what broke.
  - **Clicking a room opens it:** click the screen point of `room:prim:0` (project its centre with the page's camera via a small `window.world.screenPoint(key)` diagnostic helper added in Step 3). Then `xray.room === 'room:prim:0'`, `xray.veiled` includes `upper:prim:0`, and `xray.ownVeils` includes `header`.
  - **Host focus opens it:** `setFocus({ kind: 'level', id: 'bas' })` → `xray.room === 'room:bas:0'`. `setFocus({ kind: 'program', id: 'electronics' })` → `'project:electronics'`.
  - **Turning the camera swaps walls:** with a room open, `rotate(Math.PI)` and wait for settling. Then `ownVeils` includes `wall_back` and no longer `pier_front`.
  - **Switching rooms restores the first:** focus A, then B. Then no key of A's veiled or hidden set remains, unless it is also B's.
  - **Clearing restores everything:** record `batchSources` before opening, open a room, then `resetView`. Then `xray.room === null`, `veiled` and `hidden` are empty, and `batchSources` equals the value before.
  - **The batch skips x-rayed meshes:** with a room open, `batchSources` is below the cleared value.
  - **An update while open:** open `room:prim:0`, then `update(states[4])` and wait for settling. Then `xray.room === 'room:prim:0'` and its shell is the rebuilt entity's (a fresh `entityIds` value). No page errors.
  - **A non-room focus clears it:** `setFocus({ key: 'patio' })` (or the drones patio key), so `xray.room === null`.
  - **Picking through veils:** with `room:prim:0` open, click a point on a veiled walkway in front of it. The selection stays `room:prim:0`.
  - **Reduced motion:** a `reducedMotion: 'reduce'` page opens and clears the x-ray the same way.
- [ ] **Step 2: Run to verify it fails.** Run `node test/xray.browser.mjs ../runs/xray-03`. Expected: FAIL (`xray` undefined).
- [ ] **Step 3: Implement.**
  - **`applyXray(module)`:**
    - Clear any open x-ray.
    - For each key in `xrayBlockers(...)`:
      - `hide`: `entity.group.visible = false`.
      - `veil`: for every non-skinned mesh in `staticMeshes` and `extraMeshes`, save the material and `castShadow`, set the veil, and set `castShadow = false`. If the type is in `HIDES_INSIDE`, also hide `inside`, `extra`, every character pair, `dino`, gear and bench objects.
    - Focused room: hide `entity.shell` and add an unmerged clone of `entity.shellAsset.scene` beside it. On each named part of the clone:
      - `OWN_WALLS.always` parts take the veil.
      - The `front` and `back` lists take it per `wallVeils(yaw)`.
      - Side parts take it by the sign of their world x relative to the room, per `wallVeils`.
    - Record it all in `xray`, then `unbatch()` and `scheduleBatch()`.
  - **`clearXray()`:** restores every saved material, shadow and visibility, removes the clone, and rebatches. It skips entities already released.
  - **`scheduleBatch`:** leaves out meshes of entities in the x-ray, and the focused room's.
  - **`setFocus`:** a room module calls `applyXray`; anything else calls `clearXray`.
  - **`resetView`:** calls `clearXray`.
  - **`tick`:** when the rounded yaw changes and a room is open, re-apply.
  - **`update`:** after building, if a room is open, re-apply on the plan's module with the same key, or clear if it is gone.
  - **`pick`:** skips a hit unless the object and every ancestor are visible, and skips hits on entities veiled in the x-ray unless their module type is `room`.
  - **`getDiagnostics().xray`:** as in Interfaces.
  - **`screenPoint(key) -> { x, y }`:** projects an entity's centre to client pixels.
